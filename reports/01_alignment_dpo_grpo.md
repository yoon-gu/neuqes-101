# 레포트 1 — 정렬(alignment)이 안 올라갈 때: DPO의 측정 착시와 GRPO의 신호 분산

> **한 줄 요약.** DPO는 사실 잘 학습됐는데 *측정 방식* 때문에 실패처럼 보였고, GRPO는 8번을 돌려도 정확도가 떨어졌는데 그 원인은 하이퍼파라미터가 아니라 *학습 신호의 분산이 0* 이라는 구조적 문제였습니다. 둘 다 "모델을 더 돌리기" 전에 "무엇을 보고 있는지(측정)와 무엇이 학습을 굴리는지(신호)"를 먼저 바로잡아야 풀렸습니다.

이 레포트는 작은 한국어 GPT(`skt/kogpt2-base-v2`, 125M)를 한 자리 산술(`3 + 5 = ?`)로 정렬하면서 만난 두 가지 함정을 다룹니다. 같은 모델·같은 태스크에 DPO와 GRPO를 각각 적용했습니다.

---

## 사례 A — DPO: 실패가 아니라 측정 착시

### 1. 증상
DPO 학습 *전* 지표가 이렇게 나왔습니다.

```
BEFORE DPO - reward accuracy : 0.000   (margin>0 비율)
mean margin                  : 0.000
```

reward accuracy 0.000. 마치 "학습 전 모델이 chosen/rejected를 전혀 구분 못 한다"처럼 보입니다. 그런데 이상합니다 — 학습 전이라면 동전 던지기처럼 **0.5 근처**가 나와야 정상 아닐까요?

### 2. 틀린 해석
처음엔 "데이터나 reward 계산이 잘못됐나" 의심하기 쉽습니다. 하지만 코드는 정상이었습니다.

### 3. 전환 — 0.000의 정체
DPO의 implicit reward margin은 이렇게 정의됩니다.

$$\text{margin} = (\log\pi_\theta(y_w) - \log\pi_{\text{ref}}(y_w)) - (\log\pi_\theta(y_l) - \log\pi_{\text{ref}}(y_l))$$

학습 *전*에는 정책(policy) = 참조(reference)라서 두 항이 **정확히 상쇄**되어 margin이 모든 샘플에서 **정확히 0**입니다. 그런데 reward accuracy를 "margin > 0인 비율"로 집계하면, 0은 `> 0`이 아니므로 전부 탈락해 **0.000**이 됩니다. 즉 0.000은 "모델이 못한다"가 아니라 "전부 무승부"라는 뜻이었습니다.

### 4. 진짜 원인
**측정 방식의 함정.** 무승부(margin=0)는 개념상 50%(반반)인데, `margin > 0` 집계가 이를 0%로 깎아내렸습니다.

### 5. 해결 + 수치
무승부를 0.5로 집계하도록 한 줄만 고쳤습니다.

```python
acc_before = float((before_margins > 0).mean()
                   + 0.5 * (before_margins == 0).mean())   # 무승부 = 50%
```

| 지표 | BEFORE | AFTER |
|---|---|---|
| reward accuracy | **0.500** | **0.844** |
| mean margin | 0.000 | 12.72 |

DPO는 처음부터 잘 학습되고 있었습니다(0.844). 바뀐 것은 모델이 아니라 *자(尺)* 입니다. before/after가 0.500 → 0.844로 깔끔하게 읽히게 됐습니다.

## 사례 B — GRPO: 8번을 돌려도 떨어진 진짜 이유

### 1. 증상
GRPO를 적용하자 정확도가 학습 *후* 오히려 **떨어졌습니다.** 처음엔 SFT 없이 base 모델에 바로 GRPO를 걸었는데:

```
BEFORE GRPO - accuracy : 0.000
AFTER  GRPO - accuracy : 0.047
```

거의 안 올랐습니다(4.7%). 그래서 하이퍼파라미터를 바꿔가며 8번을 돌렸는데, **단 한 번도 개선되지 않았습니다.**

### 2. 틀린 가설들 — 8회 실험 로그
"lr·step·beta·SFT를 조정하면 오를 것"이라는 가정으로 레버를 하나씩 당겼습니다.

| # | 설정 | SFT 후(시작) | GRPO 후 | Δ |
|---|---|---|---|---|
| 1 | base 모델, GRPO 단독 (SFT 없음) | 0.000 | 0.047 | +0.047 |
| 2 | SFT 워밍스타트 + GRPO (beta 0.0) | 0.367 | 0.305 | **−0.062** |
| 3 | + KL 앵커 (beta 0.04) | 0.367 | 0.352 | **−0.016** |
| 4 | lr 2e-5, 3 epoch | 0.430 | **0.000** | **−0.430 (붕괴)** |
| 5 | lr 5e-6, 2 epoch | 0.430 | 0.398 | **−0.031** |
| 6 | SFT 5ep, beta 0.1 | 0.773 | 0.609 | **−0.164** |

패턴이 잔인할 만큼 일관됐습니다. **lr을 올리면 붕괴(0.000), 내리면 중립-소폭 하락.** 어떤 조합도 (+)를 못 만들었습니다. 이쯤 되면 "튜닝 부족"이 아니라 **구조적 문제**를 의심해야 합니다.

> 참고로 SFT 워밍스타트 자체는 큰 성공이었습니다. base 모델의 산술 정확도 0%를, GRPO 전에 산술 포맷+정답을 짧게 지도학습(SFT)하는 것만으로 **0% → 88%**까지 끌어올렸습니다. GRPO는 *없던 능력을 새로 만들지 못합니다* — 능력은 SFT가 주고, GRPO는 그 위에서 다듬는 역할입니다.

### 3. 전환 — advantage 식을 들여다보다
GRPO의 학습 신호인 advantage는 **그룹 안에서** 계산됩니다.

$$A_i = \frac{r_i - \text{mean}(r)}{\text{std}(r) + \varepsilon}$$

한 prompt에 8개 답을 생성해 그 그룹 안에서 잘한 답의 확률을 올립니다. 그런데 손계산 표를 보면:

| 그룹 reward | mean | std | advantage | 학습 신호 |
|---|---|---|---|---|
| `[0,0,0,0]` (전부 오답) | 0 | 0 | **전부 0** | **없음** |
| `[1,1,1,1]` (전부 정답) | 1 | 0 | **전부 0** | **없음** |
| `[1,0,1,0]` (섞임) | 0.5 | 0.5 | `[+1,−1,+1,−1]` | **있음** |

### 4. 진짜 원인
**학습 신호의 분산이 0.** 한 자리 산술은 prompt별 정답률이 0 또는 1로 **양극화**됩니다 — 쉬운 문제는 8개가 전부 정답, 못 푸는 문제는 전부 오답. 그러면 그룹 reward의 **std ≈ 0 → advantage ≈ 0 → gradient 0 → 아무것도 안 배웁니다.** lr을 올리면 그 잔여 노이즈만 증폭돼 붕괴했던 것입니다.

여기에 **측정의 함정**도 겹쳐 있었습니다. eval을 sampling(`do_sample=True`)으로 했더니 베이스라인이 실행마다 0.37~0.77로 출렁여서, 애초에 "GRPO가 올렸는지"를 판정할 자조차 흔들렸습니다.

### 5. 해결 + 수치
이진 보상(정답=1/오답=0)은 그대로 두고, **신호를 만들고 측정을 고정**했습니다.

```python
# (1) 측정 고정 — greedy로 베이스라인을 한 값에 못박는다
gen = model.generate(**enc, do_sample=False, num_beams=1, max_new_tokens=16)

# (2) 난이도 필터 — 그룹에 정답·오답이 섞이는 prompt만 학습셋으로 (std>0 보장)
keep = [ex for ex in pool if 0.25 <= pass_rate(model, ex["prompt"], ex["answer"]) <= 0.875]
```

여기에 GRPOConfig를 정석값으로(lr 5e-6, `loss_type="dr_grpo"`, `scale_rewards=False`, `max_grad_norm=0.2`, beta 0.04) 맞추자:

| 단계 | 정확도 |
|---|---|
| base 모델 | 0% |
| **SFT 워밍스타트 후** | **87.5%** (greedy) |
| **GRPO 후** | **89.1%** (+0.016) |

8번 만에 처음으로 **양(+)의 개선**이 나왔습니다. 개선폭은 작지만(베이스라인이 88%라 여백이 작음) 방향이 (+)로 돌아섰다는 게 핵심입니다. 참고로 epoch을 4로 늘리면 다시 과학습으로 하락(0.906 → 0.875)해서, **2 epoch이 sweet spot**이었습니다.

## 두 사례의 교훈

1. **측정을 먼저 고정하라.** DPO의 0.000도, GRPO의 출렁이는 베이스라인도, 모델이 아니라 *자(尺)* 의 문제였습니다. 자가 흔들리면 개선 여부를 판정조차 할 수 없습니다.
2. **학습엔 신호의 *분산*이 필요하다.** GRPO는 보상이 있어도 그룹 안이 전부 같으면(std=0) 아무것도 못 배웁니다. "보상 = 학습"이 아니라 "보상의 *차이* = 학습"입니다.
3. **RL은 무에서 유를 만들지 못한다.** GRPO 단독은 0%에서 못 올라옵니다. 능력은 SFT(지도학습)가 먼저 주고, RL은 그 위를 다듬습니다.
4. **일관된 실패는 튜닝이 아니라 구조를 의심하라.** 8번 모두 하락했다면 9번째 하이퍼파라미터가 아니라, 식(advantage)을 들여다볼 때입니다.
