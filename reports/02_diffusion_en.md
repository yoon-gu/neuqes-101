# 레포트 2 — 작은 diffusion LM이 영어를 쓰기까지: 유니그램 붕괴의 진짜 범인

> **한 줄 요약.** 작은 mask-diffusion LM이 영어 동화를 끝까지 생성하게 만드는 과정에서, "vocab이 너무 크다 / 학습이 부족하다"는 그럴듯한 가설로 두 번이나 고쳤는데도 모델이 계속 붕괴했습니다. 진짜 범인은 *데이터로더의 난수 설정* 이었습니다. 그리고 학습이 제대로 된 뒤에도 남은 *반복* 문제는, 모델이 아니라 *샘플러* 를 바꿔 해결했습니다.

이 레포트는 두 단계로 나뉩니다. **(A) 모델이 붕괴에서 벗어나 coherent하게 학습되기까지**, **(B) coherent하지만 반복되는 생성을 깔끔하게 다듬기까지**. 모델은 작은 `BertForMaskedLM`(hidden 256 / 4 layer, ≈3.79M), 데이터는 TinyStories, 환경은 Colab T4(fp16)입니다.

> **배경 — diffusion LM이란.** GPT처럼 왼→오로 한 토큰씩 잇는 대신, 문장 전체를 `[MASK]`로 덮었다가 *병렬로* 복원하며 생성합니다. BERT의 마스크 복원(MLM)을, 마스킹 비율을 0~100%로 가변화하고 복원을 여러 번 반복하는 방식으로 일반화한 것입니다.

---

## A부 — 붕괴에서 coherent까지

### 1. 증상
학습이 끝난 모델에게 전부 `[MASK]`인 빈 캔버스에서 생성을 시켰더니:

```
. to........... the he.. and,.. and.......,. and..... and and.
```

마침표와 `and`, `the` 같은 고빈도 토큰만 반복됩니다. train_loss는 **6.08**에서 멈췄는데, 이 값은 코퍼스의 유니그램(단어 빈도) 엔트로피와 거의 같습니다. 즉 모델은 **문맥을 보지 않고 "그냥 자주 나오는 토큰"만 외운** 상태입니다 — 전형적인 **유니그램 붕괴**입니다.

### 2. 틀린 가설들
loss 곡선이 처음부터 6.0 근처에서 평탄했습니다. 그럴듯한 원인 두 개를 차례로 고쳤습니다.

**가설 ① vocab이 너무 크다.** 처음엔 `bert-base-uncased`의 WordPiece(vocab 30522)를 썼는데, 이러면 작은 모델에서 임베딩 테이블이 파라미터의 약 70%를 잡아먹습니다. → TinyStories에 ByteLevel BPE **2048**을 직접 학습해 임베딩 비중을 13.9%로 낮췄습니다.

**가설 ② 학습이 부족하다.** diffusion은 매 step 일부 자리만 복원하므로 AR보다 오래 걸립니다. → step을 1500에서 **30000**으로 늘렸습니다.

그런데 **두 가지를 다 고친 뒤에도 train_loss가 또 6.0에서 멈췄습니다.** 같은 붕괴였습니다. 그럴듯한 가설이 둘 다 핵심이 아니었던 것입니다.

> (세 번째로 손실의 `1/t` 시간가중에서 `t`의 하한이 너무 작아(`eps=1e-3`) fp16에서 `1/t`가 폭발하는 것도 의심해 `0.02`로 올렸지만, 그것만으로도 붕괴는 풀리지 않았습니다.)

### 3. 전환 — "되는 코드"와 한 줄씩 대조
같은 레시피(vocab 2048, 30000 step, `1/t` loss)인데 다른 환경(로컬)에서 돌렸을 땐 coherent하게 나온 적이 있었습니다. 그래서 **되는 코드와 안 되는 코드를 한 줄씩 비교**했습니다. 콜레이터·손실·모델·학습 인자가 사실상 같은데, 딱 하나가 달랐습니다 — `TrainingArguments`의 **`dataloader_num_workers=2`**, 그리고 콜레이터가 전역 `torch.rand`를 쓴다는 점.

### 4. 진짜 원인
**데이터 파이프라인의 난수 상관.** `num_workers=2`로 여러 워커 프로세스가 데이터를 만드는데, 콜레이터가 `generator` 없이 전역 `torch.rand`로 마스킹 패턴을 뽑으면 워커 간 난수가 **상관(correlated)**됩니다. 그 결과 매 배치의 마스킹 다양성이 깨지고, 모델은 빈약한 마스킹 신호 위에서 유니그램으로 주저앉습니다. vocab도 step도 아니고, **"어떤 자리를 가리는가"의 다양성**이 무너진 게 범인이었습니다.

### 5. 해결 + 수치
콜레이터에 명시적 `generator`를 주고 워커를 끄자(`num_workers` 제거) 곧바로 학습이 살아났습니다.

```python
class DiffusionCollator:
    def __init__(self, tokenizer, eps=0.02, seed=42):
        self.gen = torch.Generator().manual_seed(seed)   # 명시적 generator
    def __call__(self, examples):
        t = torch.rand(B, generator=self.gen) * (1 - self.eps) + self.eps
        mask = torch.rand(B, L, generator=self.gen) < t.unsqueeze(1)
        ...
```

| 지표 | 붕괴 | 수정 후 |
|---|---|---|
| train_loss | 6.08 | **3.71** |
| 생성 | `". the the.. was"` | **`"Ben are twins. They run to the park..."`** |

인물·동작·배경이 있는 영어 동화가 나왔습니다. baseline(유니그램) 엔트로피보다 한참 아래로 내려갔다는 건, 모델이 단순 빈도가 아니라 **문맥 의존 구조**를 학습했다는 신호입니다.

## B부 — coherent하지만 반복된다 → 샘플러를 바꾼다

### 1. 증상
A부에서 살아난 모델의 생성을 자세히 읽으면 *반복*이 보입니다.

```
"...They run to the park. They run... They are happy and happy. They play and play."
```

`named named`, `play and play`처럼 같은 조각이 되풀이됩니다.

### 2. 틀린 가설
"모델을 더 키우거나 더 학습해야 하나?" — 아닙니다. 이 모델은 고정-t(0.15) 복원 정확도가 **0.717**까지 오른, 조건부 구조를 제대로 익힌 모델입니다. 문제는 모델의 확률 분포가 아니라 **거기서 문장을 어떻게 뽑아내는가**에 있었습니다.

### 3. 전환 — 모델은 그대로, 디코딩만 바꾼다
기본 샘플러는 매 step 확신이 낮은 자리를 도로 `[MASK]`로 지우는 방식인데, 한번 "안전한" 고빈도 토큰이 높은 확신을 받으면 그게 거듭 뽑히기 쉽습니다. 모델을 다시 학습하지 않고 **샘플러만** 교체했습니다.

### 4. 진짜 원인
**생성 품질은 모델만이 아니라 샘플러가 좌우한다.** 좋은 분포에서도 디코딩이 거칠면 반복에 갇힙니다.

### 5. 해결 + 수치
**carry-over semi-AR**(한번 확정한 토큰은 다음 step으로 이어받아 다시 흔들지 않음) + **반복 억제**(temperature 0.8 / top-p 0.92 / repetition penalty 1.3 / 인접 동일 토큰 금지)를 적용했습니다.

| 지표 | 기본 샘플러 | carry-over + 반복억제 |
|---|---|---|
| 4-gram 반복률 | 0.177 | **0.000** |

같은 모델(train_loss·acc 동일)인데 반복이 사라지고 한결 깔끔한 이야기가 나왔습니다.

## 이 사례의 교훈

1. **그럴듯한 가설이 곧 진짜 원인은 아니다.** vocab·step은 충분히 합리적인 의심이었지만, 둘 다 고친 뒤에도 붕괴가 남았습니다. 한 칸 더 들어간 곳(데이터 파이프라인)에 범인이 있었습니다.
2. **"되는 코드"와 한 줄씩 대조하라.** 같은 레시피가 어디선 되고 어디선 안 될 때, 그 *차이* 가 곧 범인입니다.
3. **마스킹/노이즈의 *다양성*이 신호다.** 무엇을 가리는지가 매번 충분히 달라야 모델이 문맥을 배웁니다(이 주제는 한국어 편에서 더 극적으로 반복됩니다).
4. **모델과 샘플러를 분리해서 보라.** 생성이 거칠 때, 모델을 더 키우기 전에 디코딩부터 점검하세요. 좋은 모델도 나쁜 샘플러를 만나면 반복에 갇힙니다.
