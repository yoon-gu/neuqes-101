# 실패에서 배우는 법 — 작은 모델 디버깅 레포트

작은 모델·작은 예산(무료 Colab T4, 30분)에서 학습이 *실패했다가 풀린* 과정을 사례별로 정리한 레포트 모음입니다. 각 레포트는 같은 5단 틀(증상 → 틀린 가설 → 전환 → 진짜 원인 → 해결+수치 + 교훈)로 쓰였습니다.

## 관통하는 한 가지 주제

> **작은 모델·작은 예산에서 학습이 실패할 때, 범인은 대개 "명백한 것(용량·step·하이퍼파라미터)"이 아니라 한 칸 숨은 곳 — 학습 신호의 분산, 데이터 파이프라인, 마스킹 방식 — 에 있다. 그래서 "더 키우고 더 돌리기" 대신 "측정을 고정하고 대조군으로 신호를 추적"해야 한다.**

| 사례 | 표면 가설 (틀림) | 진짜 원인 (한 칸 숨은 곳) |
|---|---|---|
| **GRPO** | "lr·step·beta 튜닝 부족" | 학습 신호 분산 — 정답률 양극화로 그룹 std≈0 → advantage 0 |
| **영어 diffusion** | "vocab 과대·step 부족" | 데이터 파이프라인 — 데이터로더 난수 상관으로 마스킹 다양성 붕괴 |
| **한국어 diffusion** | "용량·step·저마스킹" | 마스킹 방식 — 100% `[MASK]`의 복사 지름길 (→ 80/10/10) |

## 네 가지 횡단 교훈

세 레포트에서 반복해 나타나는 메타 교훈입니다.

- **① 학습엔 신호의 *분산*이 필요하다.** 신호가 0이면 아무리 돌려도 안 배운다. (GRPO advantage std=0, diffusion 마스킹 다양성)
- **② 막히면 "되는 대조군"부터 찾아라.** "왜 안 되나"보다 "무엇이 되나"가 범인을 빨리 좁힌다. (한국어: AR·표준 MLM 대조)
- **③ 표면 가설을 의심하고 ablation으로 반증하라.** 그럴듯한 원인을 고쳤는데도 안 풀리면, 한 칸 더 들어가라. (영어: vocab/step 되돌리기, num_workers 토글)
- **④ 측정을 먼저 고정하라.** 자(尺)가 흔들리면 개선 여부를 판정조차 못 한다. (GRPO sampling eval 출렁임 → greedy 고정)
