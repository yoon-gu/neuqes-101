\section{해부: 왜 naive diffusion이 무너졌나}

\section{80/10/10 마스킹}

\begin{lstlisting}
def bert_style_mask(input_ids, mask_id, vocab_size):
    masked = torch.rand_like(input_ids.float()) < 0.15
    labels = input_ids.clone()
    labels[~masked] = -100

    replace_prob = torch.rand_like(input_ids.float())
    noisy = input_ids.clone()
    noisy[masked & (replace_prob < 0.8)] = mask_id

    random_tokens = torch.randint(vocab_size, input_ids.shape)
    random_pos = masked & (replace_prob >= 0.8) & (replace_prob < 0.9)
    noisy[random_pos] = random_tokens[random_pos]
    return noisy, labels
\end{lstlisting}

\noindent\emph{위 코드 읽기.}
마스크된 위치 중 80\%는 \inlinecode{[MASK]}로 바꾸고, 10\%는 랜덤 토큰으로 바꾸며, 10\%는 원본을 유지합니다. 원본 유지가 섞이면 모델은 항상 \inlinecode{[MASK]}만 보는 상황에서 벗어나 실제 문장 토큰 주변의 조건을 더 자주 봅니다.

\begin{faqBox}{Q1. 왜 한국어에서는 영어 레시피를 그대로 쓰면 안 되나요?}
데이터와 tokenizer가 바뀌면 같은 마스킹 비율도 다른 난이도가 됩니다. 한국어 BBPE 4000에서는 높은 마스크 비율이 모델을 너무 어려운 복원 문제로 몰아 유니그램 붕괴를 만들었습니다.
\end{faqBox}

\begin{faqBox}{Q2. 80/10/10은 diffusion이라기보다 BERT MLM 아닌가요?}
맞습니다. 본 장의 안정화 레시피는 BERT MLM의 안정성을 빌립니다. 목적은 “순수한 수식”보다 T4에서 실제로 작동하는 한국어 diffusion 생성 실험을 확보하는 것입니다.
\end{faqBox}

\begin{faqBox}{Q3. \inlinecode{plain CE}로 바꾸면 \(1/t\) diffusion loss를 포기한 것 아닌가요?}
본 장에서는 한국어 안정성을 우선합니다. \(1/t\) surrogate는 이론적 연결이 분명하지만, 작은 모델·짧은 학습·한국어 BBPE 조건에서는 plain CE가 더 안정적으로 작동했습니다.
\end{faqBox}

\begin{faqBox}{Q4. fixed-\(t\) acc 0.652는 어떻게 읽어야 하나요?}
\(t=0.15\)로 일부 토큰을 가린 뒤, 가려진 위치의 원래 토큰을 top-1로 맞힌 비율입니다. naive diffusion의 0.081과 비교하면 복원 능력이 크게 개선됐습니다.
\end{faqBox}
