첫 번째 원인은 파라미터 배분입니다. Ch 32의 WordPiece vocab 30522개는 hidden 256 모델에서 임베딩 테이블만 약 7.8M 파라미터를 차지합니다. 작은 모델 전체에서 임베딩 share가 약 70\%에 이르면, 정작 문맥을 읽고 조건부 분포를 배우는 트랜스포머 본체에 남는 용량이 부족합니다. 33장은 TinyStories에 맞춘 ByteLevel BPE vocab 2048개를 직접 학습해 모델을 3.79M으로 줄이고, 임베딩 share를 13.9\%까지 낮춥니다.

두 번째 원인은 학습량입니다. diffusion LM은 AR 언어모델과 달리 모든 위치가 매 step 감독되는 구조가 아닙니다. 매 배치에서 마스크된 자리만 손실을 받으므로, 같은 수준의 조건부 구조를 배우려면 더 많은 step이 필요합니다. 이번 실행본은 T4에서 \inlinecode{max\_steps=30000}까지 학습했고, 총 18.50분이 걸렸으며 최종 \inlinecode{train\_loss}는 3.5916입니다.

세 번째 원인은 디코딩 절차입니다. Ch 32의 저신뢰 재마스킹은 방금 채운 토큰도 다시 \inlinecode{[MASK]}로 지울 수 있었습니다. 작은 모델에서는 이렇게 비단조적으로 채우고 지우는 절차가 안정적인 문맥을 만들기 어렵습니다. 33장은 block 단위로 왼쪽에서 오른쪽으로 진행하면서 한 번 확정한 토큰을 다음 step으로 그대로 넘기는 carry-over 샘플러를 사용합니다.

\section{Loss 노트: 흡수형 NELBO surrogate}

흡수형 mask diffusion에서는 시간 \(t\)에 따라 토큰 일부를 \inlinecode{[MASK]}로 흡수시킵니다. 이 장의 스케줄은 식~\eqref{eq:ch33-alpha}처럼 선형입니다.

\begin{equation}
\label{eq:ch33-alpha}
\alpha_t = 1 - t
\end{equation}

선형 스케줄에서는 시간가중이 식~\eqref{eq:ch33-time-weight}처럼 단순해집니다.

\begin{equation}
\label{eq:ch33-time-weight}
\left|\frac{\alpha'_t}{1-\alpha_t}\right| = \frac{1}{t}
\end{equation}

따라서 구현 손실은 마스크된 자리의 CE 합을 문장 길이 \(L\)로 나눈 뒤 \(1/t\)를 곱합니다. 이를 식~\eqref{eq:ch33-loss}처럼 적을 수 있습니다.

\begin{equation}
\label{eq:ch33-loss}
\mathcal{L}_{\text{surrogate}}
= \frac{1}{B}\sum_{b=1}^{B}
\frac{1}{t_b}
\frac{1}{L}
\sum_{i \in M_b}
\mathrm{CE}\!\left(p_\theta(x_i \mid x_{\setminus M_b}, t_b), x_i\right)
\end{equation}

식~\eqref{eq:ch33-loss}에서 중요한 점은 `/L`의 의미입니다. 이 항은 ELBO 자체를 그대로 출력하는 것이 아니라, ELBO와 상수배 관계에 있는 surrogate입니다. 즉 절대값을 논문식 ELBO 값처럼 해석하면 안 됩니다. 다만 같은 실험 안에서 학습 방향을 만들고 loss 추이를 비교하기에는 충분합니다. 반면 \(1/t\)는 단순 상수배가 아니라 시간별 가중 자체를 바꾸므로, 흡수형 diffusion의 학습 성질을 보존하려면 빼면 안 됩니다.

def diffusion_loss(model, input_ids, attention_mask):
    batch, seq_len = input_ids.shape
    t = torch.rand(batch, device=input_ids.device).clamp_min(0.02)
    mask_prob = t[:, None].expand_as(input_ids)
    can_mask = attention_mask.bool()
    mask = (torch.rand_like(mask_prob) < mask_prob) & can_mask

    noisy = input_ids.clone()
    noisy[mask] = tokenizer.mask_token_id
    logits = model(noisy, attention_mask=attention_mask).logits

    ce = F.cross_entropy(
        logits[mask],
        input_ids[mask],
        reduction="none",
    )
    weight = (1.0 / t).repeat_interleave(mask.sum(dim=1))
    return (ce * weight).sum() / (batch * seq_len)
\end{lstlisting}

\begin{codeRead}
핵심은 \inlinecode{t}와 \inlinecode{weight = 1.0 / t}입니다. 각 샘플마다 마스킹 비율을 뽑고, 마스크된 자리에서만 CE를 계산한 뒤 식~\eqref{eq:ch33-time-weight}의 시간가중을 곱합니다. 나머지 토큰은 손실을 받지 않으므로, 이 학습은 CausalLM처럼 모든 위치를 매번 감독하지 않습니다.
\end{codeRead}

def fixed_t_acc(t_val=0.15, n=128):
    cor = tot = 0
    for ex in lm_val.select(range(min(n, len(lm_val)))):
        ids = torch.tensor(ex["input_ids"])
        m = torch.rand(len(ids), generator=g) < t_val
        if not m.any():
            m[0] = True
        inp = ids.clone()
        inp[m] = tokenizer.mask_token_id
        with torch.no_grad():
            pr = model(inp.unsqueeze(0).to(device)).logits[0].argmax(-1).cpu()
        cor += (pr[m] == ids[m]).sum().item()
        tot += int(m.sum())
    return cor / tot

print(f"[진단] 고정-t(0.15) top-1 accuracy = {fixed_t_acc():.3f}")
\end{lstlisting}

def rep4(text):
    toks = text.split()
    if len(toks) < 5:
        return 0.0
    grams = [tuple(toks[i:i+4]) for i in range(len(toks)-3)]
    return 1.0 - len(set(grams)) / len(grams)

\section{FAQ}

\begin{faqBox}{Q1. vocab을 2048로 줄이면 표현력이 부족하지 않나요?}
일반적인 대규모 웹 말뭉치라면 부족할 수 있습니다. 하지만 이번 데이터는 TinyStories이고, 목표는 작은 diffusion LM이 조건부 구조를 배울 수 있는지 확인하는 것입니다. Ch 32에서는 vocab이 너무 커서 임베딩이 모델 대부분을 차지했습니다. 2048 BPE는 어휘 표현력을 조금 줄이는 대신 본체가 문맥을 학습할 용량을 확보합니다.
\end{faqBox}

\begin{faqBox}{Q2. \inlinecode{train\_loss} 3.59만 보면 충분히 좋은 모델이라고 말할 수 있나요?}
아닙니다. loss만으로는 생성 품질을 판단하기 어렵습니다. 그래서 이 장은 고정-\(t\) top-1 accuracy 0.717, KL 0.78, 4-gram 반복률 0.177 \(\to\) 0.000을 함께 봅니다. loss는 학습이 진행됐다는 신호이고, 세 진단값은 모델과 샘플러가 실제로 개선됐는지 확인하는 별도의 증거입니다.
\end{faqBox}

\begin{faqBox}{Q3. KL 0.78은 왜 좋은 신호인가요? KL은 작을수록 좋은 것 아닌가요?}
여기서 비교 대상은 정답 분포가 아니라 코퍼스 유니그램 분포입니다. 생성 분포가 유니그램과 거의 같다면 모델이 문맥을 보지 않고 단어 빈도만 흉내 내는 상태일 수 있습니다. 따라서 이 진단에서는 KL이 0 근처로 붙는 것이 오히려 붕괴 신호입니다. 0.78은 생성이 단순 빈도표와 다르게 움직인다는 뜻입니다.
\end{faqBox}

\begin{faqBox}{Q4. carry-over 샘플러는 AR 생성과 같은 것인가요?}
완전히 같지는 않습니다. AR은 매 step 다음 한 토큰만 예측하고 KV-cache로 이어 갑니다. carry-over 샘플러는 diffusion 모델의 전체 로짓을 반복해서 보되, block 안에서 이미 확정한 토큰을 다시 지우지 않는 방식입니다. 왼쪽에서 오른쪽으로 확정된 문맥이 쌓인다는 점에서는 AR에 가까운 안정성을 일부 빌려옵니다.
\end{faqBox}

\begin{faqBox}{Q5. 왜 \inlinecode{[MASK]} 토큰을 생성 결과에서 막아야 하나요?}
\inlinecode{[MASK]}는 학습 중 노이징 상태를 나타내는 토큰이지 최종 텍스트에 남아야 할 단어가 아닙니다. 디코딩 중 \inlinecode{mask\_id} 로짓을 \(-\infty\)로 막지 않으면 모델이 빈칸 자체를 답으로 내놓을 수 있습니다. 샘플러는 모든 자리가 실제 토큰으로 확정되도록 \inlinecode{[MASK]} 생성을 차단해야 합니다.
\end{faqBox}

\begin{faqBox}{Q6. Ch 24 AR 모델과 Ch 33 diffusion 모델 중 어떤 쪽을 실무 기준선으로 삼아야 하나요?}
작은 모델과 제한된 GPU 예산에서는 AR을 기준선으로 삼는 편이 현실적입니다. \ref{ch:24}장은 1500 step으로 매끄러운 결과를 얻지만, 33장은 30000 step을 써야 Ch 32 붕괴를 벗어납니다. diffusion은 구조적으로 흥미롭지만, 학습 신호와 디코딩 비용을 함께 고려해야 합니다.
\end{faqBox}

\begin{faqBox}{Q7. 이 장의 결과를 더 개선하려면 무엇을 먼저 바꿔야 하나요?}
