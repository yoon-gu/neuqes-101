# notebook → WikiDocs 변환

챕터 노트북을 WikiDocs 연동용 `pages/NN-slug*.md`(장 1 + 절 여러 개)로 바꾼다.

**호출**: 보통 사용자가 **변환할 챕터를 인자로** 주며 직접 호출한다. 모델이 변환이 필요하다고 판단하면 자율적으로 호출해도 된다.
```
/notebook-to-wikidocs 7                # 7장
/notebook-to-wikidocs 7 24             # 여러 장
/notebook-to-wikidocs 07_bert_pipeline # 폴더명으로도 가능
/notebook-to-wikidocs --all            # 전체 (사용자 확인 후)
```

**핵심 원칙**
- 코드를 실으면 그 코드의 **실제 실행 결과**도 함께 싣는다 — 가짜 출력을 지어내지 않는다.
- 같은 `.md`가 **웹(WikiDocs)·PDF·EPUB 세 타깃** 어디서도 깨지지 않게 한다(서점 판매엔 EPUB 필수).

설계 결정·실측 기록은 같은 폴더의 `DESIGN_NOTES.md` 참조.

## 파이프라인

`① 실행 결과 확보(executed/) → ② 변환(build_wikidocs.py) → ③ 검증(check_wikidocs_md.py) → ④ 설명 덧붙이기(코드 설명 + 결과 해석)`

### ① 실행 결과 확보 — `executed/<폴더>.ipynb`

챕터의 진짜 출력은 **Colab에서 실행해야** 나온다. **colab-cli 를 먼저 쓴다(권장).** 두 경로 모두 출력 포함
`executed/<폴더>.ipynb` 를 만들고, 같은 실행 로직(해시 멱등·`executed_from` 도장)을 공유한다.

- **C. colab-cli (1순위·권장)** — [`google-colab-cli`](https://github.com/googlecolab/google-colab-cli)로 **터미널에서** VM 할당→실행→`colab download` 회수. 결과를 로컬로 받아 **PAT 불필요**, 브라우저를 안 열어도 되고 **인증만 1회 해두면 스킬/에이전트가 직접 실행**할 수 있다.
  - `./executed/run_via_cli.sh` — **인자 없으면 전 챕터**, **`7 24` 처럼 주면 그 챕터만**(REPO 는 git origin 에서 자동 인식). 챕터별 새 VM·일시드롭 1회 재시도·resume(이미 ok 면 skip, `FORCE=1` 로 무시).
  - **사전 1회**: `uv tool install "git+https://github.com/googlecolab/google-colab-cli"`(issue #14 keep-alive 수정본 — PyPI v0.5.11 이하는 VM 이 ~11분에 idle-prune 돼 무거운 챕터 실패) + `colab --auth=oauth2 whoami`(동의화면 "모두 선택"). **과금 방지로 결제수단 없는 무료 계정** 권장. 자세한 건 `executed/README.md`.
  - 수정본 기준 **전 32챕터 완주**(25·24분, 27·19분 포함, 실측). 무료 T4 표준 idle timeout 은 ~90분.
- **A. 브라우저 러너 `executed/run_on_colab.ipynb` (폴백)** — **다음 경우에만**: ⓐ Windows(colab-cli 미지원), ⓑ CLI 인증을 못 쓰는 상황, ⓒ (구버전 colab-cli 사용 등으로) 무거운 챕터가 11분 캡에 막힐 때. Colab T4에서 열어 실행 → **본인 fork**로 커밋·푸시(PAT은 `getpass`, 미저장). 이 경로는 **사람이 직접** 한다.

- **멱등·재개**: clean 노트북 해시를 실행본에 도장 → 안 바뀐 챕터는 skip, 세션이 끊겨도 이어 채운다. 챕터별·총 소요시간 출력.
- **repo-agnostic**: VM 에서 clone 만 하므로 REPO 는 git origin 에서 자동 인식(원본 push 권한 불필요).

**변환 전 반드시 확인**: 변환할 챕터의 `executed/<폴더>.ipynb` 가 있는지 먼저 본다.
**없으면 합성으로 조용히 넘어가지 말고**, 먼저 **C(colab-cli)** 로 실행해 `executed/<폴더>.ipynb` 를 만든다
(macOS/Linux·인증돼 있으면 스킬이 직접 실행 가능). CLI 를 못 쓰면 **A(브라우저 러너)** 로 사람이 실행하도록 안내하고 멈춘다.

### ② 변환 — `scripts/build_wikidocs.py`

챕터 인자: 번호(`7`/`07`)·폴더명(`07_bert_pipeline`), 여러 개 가능. 전체는 `--all`
(**대량 실행이라 사용자 확인 후**). 제목·장→절 분할은 자동.

```bash
python3 .claude/skills/notebook-to-wikidocs/scripts/build_wikidocs.py 7 24    # executed/<폴더>.ipynb 자동 사용
python3 .claude/skills/notebook-to-wikidocs/scripts/build_wikidocs.py --all   # 전체 (사용자 확인 후)
```

**출력 원천 우선순위**(셀마다 자동): `--executed-notebook` > `executed/<폴더>.ipynb` > `--execute` > 합성.
실제 결과는 `▶ 실행 결과`, 합성 골격(값 `...`)은 `▶ 출력 형태`로 라벨을 구분한다. 합성 로직은 tex와 단일 출처를 공유한다(재구현 금지 — import해서 사용).

**전자책 안전 출력**(자동) — [wikidocs 전자책 작성시 주의할 점](https://wikidocs.net/198723) 기준:
- 출력 기본 스타일 `code` — HTML `<pre>` 박스는 PDF에서 전멸하고 EPUB XML이 깨져 회피.
- 규칙 자동 방어: 헤딩 위아래 빈 줄 삽입, 수평선 제거, 본문 H1→H2 강등, 각주 이름 유니크화, 윈도우 경로(`C:\`)→인라인 코드.
- 노이즈 필터(HF Hub 인증·`tqdm`·`generation_config` 보일러플레이트) + EPUB 긴 산문 줄 트렁케이트.
  단 **출력이 곧 학습 내용인 토큰화 챕터(08·15·22)는 opt-out**(원본 보존, 표는 항상 보존).

산출물: `pages/NN-slug.md`(개요) + `-{practice,anatomy,variation,wrapup}.md`(절), 그림 `assets/NN-slug-outK-V.png`,
`TOC.md`(해당 장 블록만 교체, 나머지 번호 순서 보존). 챕터별 실패는 격리되어 배치를 멈추지 않는다.

**부록 노트북**(자동, 이슈 #143) — 챕터 폴더 안의 부록 노트북도 같은 실행에서 페이지 1장으로 나온다.
- **두 가지 명명을 모두 잡는다**: `<폴더>_<suffix>.ipynb`(12·14·18·20·31·34) 과 `appendix_<suffix>.ipynb`(07·09·10·21·23·27·29·31). `executed/colab_cli_exec.py` 가 89a4754 에서 맞춘 규약과 같다.
- 페이지는 어느 명명이든 `pages/NN-slug-<suffix>.md` 한 형식(`appendix_compute_budget` → `21-en_bert_classify-compute_budget.md`) — 파일을 옮기지 않고 산출물 층에서 규약을 통일한다.
- 목차 항목은 **표준 절 다음 번호 하나**로 붙는다(`21-4. 부록 — fair-compute 비교 …`). 제목은 부록 H1 에서 장 접두(`Chapter 21 `·`Ch 20·22 `)와 말미 이슈 참조(`(이슈 #19)`)를 뗀 것. 본편과 달리 실습/해부/변형으로 쪼개지 않는다 — 부록은 한 실험을 끝까지 따라가는 글이고 기존 부록 페이지도 모두 단일 페이지다.
- **실행본이 없으면 페이지를 만들지 않고** 만드는 법을 알려 준다(`./executed/run_via_cli.sh <부록 stem>`). 출력이 빈 부록 페이지는 "가짜 출력 금지"와 같은 이유로 없느니만 못하다.

**노트북 상대 링크 → Colab URL**(자동, 이슈 #143) — 본문의 `](./appendix_x.ipynb)` 류 링크는 WikiDocs 에서 `https://wikidocs.net/appendix_x.ipynb` 로 풀려 **독자를 책 밖(위키독스 홈)으로 내보낸다.** 페이지 id 는 빌드 시점에 알 수 없고 책 안에 페이지 간 상대 링크 규약도 없으므로(페이지 목록은 `[[SubPages]]` 매크로 담당), GitHub·WikiDocs·PDF·EPUB 어디서나 살아 있는 **Colab URL** 로 바꾼다. 바꾸는 대상은 **그 챕터 폴더에 실제로 있는 노트북**뿐 — 없는 파일명은 오타일 수 있어 그대로 두고 검수에서 드러나게 한다.

그림 파일명의 `-V`는 **버전 postfix**다. WikiDocs는 파일명이 같으면 내용이 달라도 캐시된 이미지를 그대로 보여주므로, 같은 출력(`outK`)을 다시 그릴 때마다 `-1` → `-2` → `-3` 으로 버전을 올려 매번 새 파일명을 만든다. 페이지가 더는 안 가리키는 옛 버전(과 버전 도입 전 무버전 `outK.png`)은 빌드가 자동으로 지운다(`build_wikidocs.py:_next_image_version`).

**절 제목 형식**(자동 통일) — 절 제목은 항상 `키워드: 소개` 한 형식으로 맞춘다(`_normalize_subtitle`):
- 실습 → `실습: <간단한 소개>`, 변형 → `변형: <간단한 안내>`, 해부 → `해부: <간단한 소개>`.
- 정리와 FAQ(wrapup)는 소개 없이 항상 `정리와 FAQ` 그대로(노트북 헤더로 덮어쓰지 않음).
- 노트북 헤더가 `실습 2:`·`변형 —`·`… 실습`(키워드 말미)처럼 제각각이어도 키워드+순번+구분자를 떼어 `키워드: 나머지`로 통일한다(구분자는 `:` 고정, `—` 금지). 키워드만 있고 소개가 없으면 키워드만 남는다.
- 노트북 작성 시에도 이 형식(`실습: 소개` / `변형: 안내`)으로 헤더를 쓰면 변환이 그대로 보존한다.

**실습 Colab 링크**(자동) — 각 장 `*-practice.md` 맨 위에 그 장 노트북(`NN_slug/NN_slug.ipynb`)을 여는 **Colab 바로 열기 링크**를 단다. repo 는 git origin 에서 자동 인식. 배지 이미지(외부 SVG)는 EPUB/PDF에서 깨지므로 **전자책 안전한 텍스트 링크**로 넣는다(린터 E4 회피). 개요·해부 등 다른 절에는 달지 않는다.

### ③ 검증 — `scripts/check_wikidocs_md.py`

변환 후 **린터로 전자책 규칙을 전수 검사**한다(위반 0 확인). 변환기가 자동 방어하지만, 변환기와 별개로
**회귀·수기 편집**을 잡는 독립 점검이다(코드펜스 안은 제외).

```bash
python3 .claude/skills/notebook-to-wikidocs/scripts/check_wikidocs_md.py   # pages/*.md 전체. 위반 시 종료코드 1
```

이어서 사람이 확인: 코드 셀에 `▶ 실행 결과`가 붙었는가(`<!-- 실행 결과 없음 -->`이면 출력 없는 셀이 맞는지),
`assets/` PNG 생성·상대경로(`../assets/...`), 첫 H1 제거(페이지 제목은 `TOC.md` 담당) 여부.

### ④ 설명 덧붙이기 — 코드 설명 + 위 코드 읽기 + 결과 해석 (스킬이 직접 작성 — 스크립트 아님)

②변환·③린터를 통과한 뒤의 `pages/*.md` 는 코드와 출력 위주라 그대로 두면 **'코드만 잔뜩'** 이 된다.
**코드 블록 앞에는 짧은 코드 설명**을, **코드 블록 뒤에는 `위 코드 읽기`** 를, **의미 있는 출력 뒤에는 결과 해석**을 직접 덧붙여 읽을거리를 만든다.
스크립트가 아니라 **스킬 사용 시 직접** 쓴다. (셋 다 페이지 수기 편집이라 재생성 시 사라짐 — 재변환 후 다시 덧붙인다.)

**(보조 도구) `scripts/migrate_enrichment.py` — 재변환 시 기존 ④ 자동 이식**: 변환기를 고쳐 **이미 ④가 들어간 페이지를 다시 찍어낼 때**, 손으로 다시 쓰는 대신 직전 git 페이지의 A/B/C 산문을 **코드셀 단위로 새 페이지에 되붙인다**. ④ 의 수기 원칙을 자동화한 것이라 정규 파이프라인(①~③)엔 안 들어가고, 재변환 직후 필요할 때만 쓴다.
```bash
python3 .claude/skills/notebook-to-wikidocs/scripts/migrate_enrichment.py <장> --old-ref HEAD
```
- B(위 코드 읽기)·C(결과 해석)는 마커가 분명해 그대로 이식. A(코드 앞 설명)는 마커가 없어 표·인용·노트북 본문과 겹치는 것은 건너뛰는 best-effort(구버전 내용 부활 방지).
- **실행본이 바뀌면 보존하지 않는다**: 현재 `executed/<장>.ipynb` 가 `--old-ref` 대비 코드·출력이 달라졌으면(재실행으로 결과가 바뀌면) 옛 ④(특히 결과 해석)는 더는 맞지 않으므로 **이식을 건너뛰고**(`[skip]` 출력) 페이지를 갓 재변환된 상태(④ 없음)로 둔다 → ④ 를 **새로 작성**한다. 정말 강행해야 하면 `--force`.
- 부록 페이지(`-data_scaling`·`-compute_budget` 등)는 대상에서 제외한다 — ②가 부록 노트북에서 새로 찍어내고, 아직 ④를 얹지 않은 페이지들이다. 적용 후 ③린터·중복/순서 점검 권장.

**기존 변환본 보존 — 없는 것만 추가**: ②변환은 `pages/*.md` 를 노트북에서 새로 찍어내므로, **이미 ④가 적용돼 손으로 다듬은 A/B/C 산문을 통째로 덮어쓴다.** 그래서 ④를 다시 할 때는 **백지에서 새로 쓰지 말고**, **현재 브랜치에 이미 있는 직전 `pages/*.md` 를 기준선으로 삼아** 거기 이미 있는 A/B/C 는 **코드·`▶ 실행 결과` 출력이 바뀌지 않은 한 그대로 보존**하고 **빠진 항목만 새로 더한다**. 구체적으로:
- **변환 전 보존**: 재변환하기 전에 기존 `pages/<장>*.md` 를 확보해 둔다 — 이미 브랜치에 커밋돼 있으니 **현재 워킹트리의 그 파일을 그대로 보면 된다**(별도 브랜치를 뒤질 필요 없음). ②변환이 산문을 날린 뒤, 새 골격에 기존 산문을 **그대로 되붙인다** — 다른 표현으로 고쳐 쓰지 않는다.
- **코드/출력 동일성 확인**: 기준선의 A/B/C 가 가리키는 코드 줄·출력 값이 새 변환본과 **글자까지 같으면** 그 설명은 여전히 정확하므로 보존. 코드나 실측 출력이 **실제로 바뀐 부분만** 그에 맞춰 갱신한다(바뀐 값에 맞춰 결과 해석 수정 — 가짜 출력 금지 원칙).
- **추가만**: 기준선에 (B)`위 코드 읽기`가 없고 (A)·(C)만 있으면, **(A)·(C)는 한 글자도 안 건드리고** 코드 셀을 조각내 (B)만 새로 끼워 넣는다. 반대로 (A)가 비면 (A)만 보강한다.
- **재작성 금지 신호**: 같은 출력을 두고 기준선과 다른 문장으로 결과 해석을 새로 쓰면 그건 보존이 아니라 덮어쓰기다 — diff 가 "내용 추가"가 아니라 "문장 교체"로 나오면 멈추고 기준선 문장을 되살린다.

#### (A) 코드 설명 — 코드 블록 앞 2-3문장

앞 설명 없이 코드 블록이 이어지면 그 블록 **바로 앞**에 무엇을 하는 코드인지 **2-3문장**으로 안내한다.
무슨 일을 하는지에 더해, 왜 그렇게 하는지/무엇을 눈여겨볼지까지 짧게 곁들여 독자가 코드를 읽기 전에 맥락을 잡게 한다.

- 형식: 코드 펜스(```` ```python ````) **바로 앞**에 평범한 2-3문장(머릿말·이모지 없이), 위에 빈 줄. 같은 줄에 코드 시작 금지.
- 근거: 코드 자체 + 노트북 마크다운. 이미 앞에 충분한 산문이 있으면 **중복 추가 금지**(1문장짜리 설명만 있으면 2-3문장으로 보강).
- 건너뜀: `import`·`!pip install`·`!nvidia-smi` 같은 사소한 셀은 설명하지 않는다.
- 톤: 존댓말·간결, 동작 중심(예: "별점(0-4)을 1-5 float 로 바꿔 회귀 라벨을 만듭니다. Trainer 는 `labels` 컬럼을 그대로 받아 MSELoss 를 적용하므로, 라벨을 float 로 두는 것이 핵심입니다.").

#### (B) 위 코드 읽기 — 코드 셀을 조각으로 쪼개고 각 조각 **뒤** 설명

(A)의 앞 설명은 그대로 두고, **하나의 코드 셀(②변환이 만든 한 코드 펜스)을 논리 단위 조각(한 아이디어 = 대략 2~4줄)으로 쪼갠 뒤, 각 조각 바로 뒤에** `**위 코드 읽기**` 문단을 붙여 그 조각의 핵심 줄을 풀어 설명한다.
앞(A)이 "이제 무엇을 할지" 맥락이라면, (B)는 셀을 조각내어 "방금 그 줄이 무슨 의미인지"를 정독시키는 자리다.
라벨·포맷은 인쇄책(`book/`)의 `위 코드 읽기`(단일 출처 `book/tools/notebook_to_tex.py` 의 `code_walkthrough()`)와 통일하되,
거기서 쓰는 **패턴 매칭 채움글(예: "이후 분석에서 사용할 값을 준비합니다")이 아니라 실제 의미를 직접 쓴다** — 이게 수기 작성의 핵심 이점.

- **셀 쪼개기**: 한 셀의 코드를 의미 단위로 여러 코드 펜스로 나눈다. ②변환은 셀당 한 펜스를 만들지만, **④에서 직접 쪼갠다**(한 조각 = 한 아이디어). `import`·`!pip`·`!nvidia-smi`·단순 `print()`/`display()` 전용 셀은 쪼개지 않는다.
- **원문 불변 — 쪼개기만 한다**: 쪼개는 과정에서 **기존 코드·출력 내용을 절대 수정·삭제·재배열하지 않는다.** 하는 일은 오직 **코드를 라인의 의미 단위로 나누는 것뿐** — 코드 글자, 주석, 들여쓰기, 그리고 `▶ 실행 결과` 블록 안의 출력은 한 글자도 바꾸지 않고 그대로 보존한다(가짜·변형 출력 금지 원칙). 조각들을 다시 이으면 원래 셀의 코드와 정확히 동일해야 한다.
- **각 조각 뒤 `위 코드 읽기`**: 조각 펜스 닫는 ```` ``` ```` 다음 빈 줄 → `**위 코드 읽기**` 를 문단 머리에 run-in 으로 두고 같은 문단에 본문을 잇는다. 머릿말·이모지 없이, 존댓말·간결. 짚을 핵심이 없는 조각은 생략한다.
- **출력 위치**: `▶ 실행 결과` 는 원래 셀 **전체**의 출력이므로 조각마다 나누지 말고 **마지막 조각 뒤에 한 번** 둔다.
- **코드 조각으로 참조**: `N행의` 같은 **줄번호 표기는 쓰지 않는다**(WikiDocs 코드펜스는 줄번호가 렌더되지 않음). 대신 **실제 코드 조각을 백틱**으로 인용한다 — 예: `` `shuffle(seed=42).select(...)` 에서는 … ``.
- **핵심 의미 단위만**: 모델 학습·토큰화·Loss/`problem_type`·freeze 처럼 **학습자가 놓치기 쉬운 의미 단위만** 짚는다. **모든 줄을 기계적으로 해설하지 않는다**(AGENTS.md `book/` 규칙과 동일).
- **(A)와 중복 회피**: 앞 설명에서 이미 말한 내용을 그대로 되풀이하지 않는다. (B)는 조각별로 더 구체적으로 — 어떤 식별자가 무슨 역할인지 — 들어간다.
- **근거**: 코드 자체 + 노트북 마크다운. 거기 없는 새 사실을 지어내지 않는다.
- 예(토큰화 셀을 두 조각으로 쪼갠 경우): 첫 조각(`train_ds = ds["train"].shuffle(seed=42).select(range(4000))`) 뒤 → `**위 코드 읽기** `` `shuffle(seed=42).select(range(4000))` `` 에서는 전체에서 일부만 추려 T4 30분 제약을 맞춥니다(seed 고정으로 재현성 확보).` / 둘째 조각(`tokenize_fn` 정의) 뒤 → `**위 코드 읽기** `max_length=128` 로 자르고 별점 0–4 를 1–5 float 으로 바꾸는데, 이 float 라벨이 핵심으로 Trainer 가 dtype 을 보고 분류가 아닌 회귀(MSELoss)로 처리합니다.`

#### (C) 결과 해석 — 의미 있는 출력 뒤

생성된 `pages/*.md` 의 **의미 있는 실행 결과**(`▶ 실행 결과`) 뒤에 짧은 **결과 해석**을 덧붙인다.

- 근거: 해당 챕터 **노트북의 마크다운 셀 설명 + 실제 출력**. 거기 없는 새 사실을 지어내지 않는다.
- **기존 내용은 삭제·수정하지 않는다** — 출력 블록 뒤에 머릿말 `**결과 해석**` 을 붙여 **추가만** 한다.
- **형식 고정**: `**결과 해석**` 을 **단독 줄**로 두고, 위·아래 빈 줄 + 그다음 줄부터 본문.
  같은 줄에 본문을 붙이지 않는다(`**결과 해석** 본문 …` 금지 — 전자책 렌더·일관성 때문). 출력 블록의 닫는 ``` 바로 다음에 빈 줄 → 헤더 순서.
- 대상: 해석이 도움 되는 출력(학습 지표·분류 결과·표·생성 샘플 등). import 로그 등 사소한 출력은 건너뛴다.
  **개요(`NN-slug.md`)·FAQ뿐인 wrapup 절은 보통 `▶ 실행 결과`가 없어 대상이 아니다** — 실제 출력이 실린 practice·anatomy·variation 절이 주 대상.
- 분량·톤: **1~2문장**으로 간략히 — 그 출력이 무엇을 보여주는지/왜 그런지를, **챕터 노트북 문체 + 전자책(존댓말·간결)** 에 맞춘다.
- **노트북 산문의 추정치(예상 소요시간·예상 loss)와 실행본 실제값이 다르면 실제값을 기준으로 해석**하고(가짜 출력 금지 원칙), 그 불일치는 **사용자에게 보고**한다 — 실행본이 의도와 다른 설정으로 돌았을 수 있다.
- 챕터를 병렬 서브에이전트로 나눠 작성할 때도 **위 형식 규칙을 각 에이전트에 명시**한다(헤더 인라인 등 형식이 갈리지 않게).

## 주의

- **원본 챕터 노트북(`<NN>_<slug>/*.ipynb`)·인쇄책 tex(`book/chapters/*.tex`)·이미 있는 실행본(`executed/<폴더>.ipynb`)은 읽기만 하고 절대 수정하지 않는다.** 위키독스 작업이 새로 쓰는 산출물은 `pages/`·`assets/`·`TOC.md`뿐이다. 학습 자료(노트북)·인쇄책(tex)은 별도 워크플로 소관이라 회귀를 막기 위해 손대지 않는다(출력 렌더 로직만 tex→md로 포팅). 실행본은 **없을 때만** ①에서 새로 만들고(해시 멱등·resume), **이미 있으면 그 출력을 그대로 신뢰해 다시 실행·덮어쓰지 않는다**(`FORCE=1` 등으로 의도적으로 재생성할 때만 예외).
- 한 번에 한 챕터씩, 검증 안 된 챕터를 두고 다음으로 넘어가지 않는다(CLAUDE.md 워크플로).
- 챕터 단위로 의미 있게 커밋. WikiDocs 출판 워크플로는 메모리 `wikidocs-publishing` 참조.
